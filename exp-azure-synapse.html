Azure Synapse MPP & Speed Serving Layer

Traditional SMP databases cannot scale to petabyte-range queries. Azure Synapse SQL DW uses a Massively Parallel Processing (MPP) architecture with 60 distributed compute nodes, Clustered Columnstore Indexes (CCI), and PolyBase. For low-latency clients, an in-memory Azure Redis Cache and globally distributed Azure Cosmos DB form the serving layer.

flag Aim of the Experiment

To contrast Hash vs. Round-Robin distribution strategies in Synapse SQL DW, measure query execution plans across 60 compute nodes, benchmark Redis Cache sub-millisecond read latency against relational queries, and configure Cosmos DB multi-region consistency.

table_chart MPP Table Distribution Strategies

  • Hash Distribution: Rows assigned based on a deterministic hash of a key (e.g., DeviceId). Ideal for large fact tables to eliminate DMS data shuffling during joins.
  • Round-Robin: Rows distributed evenly across 60 distributions. Ideal for staging tables.
  • Replicated: Full copy kept on each compute node. Best for small dimension tables (< 2GB).
