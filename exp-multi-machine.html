2. Multi-Machine Apache Kafka Architecture (Broker, Producer & Consumer)

flag Aim

To design, configure, and operate a distributed Apache Kafka cluster across three independent network machines (Machine 1: KRaft Broker & Controller, Machine 2: Remote Producer, Machine 3: Remote Consumer), establishing proper listener advertisement, opening firewall ports, and streaming real-time event payloads.

lightbulb Understand the Multi-Machine Networking Mechanism

The Core Challenge: In a single-machine setup, all components communicate via localhost. However, in a multi-machine architecture, Apache Kafka relies on a Metadata Protocol. When a Producer on Machine 2 or Consumer on Machine 3 initiates a connection to Machine 1, the Kafka broker responds with a metadata package containing the advertised.listeners value.

If advertised.listeners is mistakenly left as localhost, the remote Producer and Consumer receive localhost:9092 in the metadata response and erroneously attempt to send/receive messages to their own local loopback interface, resulting in timeout and disconnect errors. Therefore, advertised.listeners MUST explicitly advertise Machine 1's actual LAN IP address (e.g. PLAINTEXT://192.168.1.10:9092).

calculate Offset Tracking & Consumer Lag Formulation

Each topic partition constitutes an ordered, immutable sequence of records. Each record within a partition is assigned a sequential identifier known as an offset. The real-time synchronization lag of a consumer is computed mathematically as:

\( \text{Consumer Lag}(P_i) = \text{LogEndOffset}(P_i) - \text{CurrentConsumerOffset}(P_i) \)

Where:

  • \( \text{LogEndOffset}(P_i) \): The offset of the next message to be appended to partition \( P_i \) by the producer.
  • \( \text{CurrentConsumerOffset}(P_i) \): The latest committed offset read and acknowledged by the consumer group.
  • \( \text{High Watermark} \): The highest offset committed and replicated across all in-sync replicas (ISR).

format_list_numbered Step-by-Step Procedure

1 Phase 1: Machine 1 (Kafka Broker Configuration)

  1. Open C:\kafka4.3.1\config\server.properties and set the network listeners: 
    listeners=PLAINTEXT://0.0.0.0:9092,CONTROLLER://0.0.0.0:9093
advertised.listeners=PLAINTEXT://192.168.1.10:9092
controller.quorum.voters=1@localhost:9093
log.dirs=C:/tmp/kraft-combined-logs
  2. Open inbound port 9092 on Machine 1 via PowerShell (Administrator): 
    New-NetFirewallRule -DisplayName "Kafka 9092" -Direction Inbound -LocalPort 9092 -Protocol TCP -Action Allow
  3. Generate Cluster UUID and format storage: 
    kafka-storage.bat random-uuid
kafka-storage.bat format -t <CLUSTER_UUID> -c C:\kafka4.3.1\config\server.properties --ignore-formatted
  4. Start the Kafka server: 
    kafka-server-start.bat C:\kafka4.3.1\config\server.properties

2 Phase 2: Machine 2 (Producer Initialization)

  1. Verify connectivity to Machine 1 on port 9092: 
    Test-NetConnection -ComputerName 192.168.1.10 -Port 9092
  2. Create the topic remotely from Machine 2: 
    kafka-topics.bat --create --topic fsd-topic --bootstrap-server 192.168.1.10:9092 --partitions 1 --replication-factor 1
  3. Launch the interactive Console Producer: 
    kafka-console-producer.bat --topic fsd-topic --bootstrap-server 192.168.1.10:9092

3 Phase 3: Machine 3 (Consumer Initialization)

  1. Launch the Console Consumer to stream from offset 0: 
    kafka-console-consumer.bat --topic fsd-topic --from-beginning --bootstrap-server 192.168.1.10:9092
  2. Type messages into Machine 2's producer prompt and observe instantaneous real-time arrival on Machine 3.
